- (note) Source: docs/SSE-Finance-Architecture.md, docs/SSE-Finance-Tasks.md, docs/sse-finance-onboarding-runbook.md, docs/sse-finance-trait-imports.md — pre-sorted, rich design docs (status: design/planning, no implementation yet per SSE PRODUCT-LINES.md). Structured input, no elicitation needed.
- (decision) Why = opportunity to capture: SSE's existing engine (vault/pool/liquidation/oracle/governance, v8) is a mint-based CDP; SSE Finance inverts one axiom (mint-on-demand -> transfer from a finite LP pool) to become an interest-free Liquity-style lending market, reusing ~80% of proven SSE Core patterns as source (not live dependency).
- (capability) CAP-1 intent: Borrower deposits multi-asset collateral (sBTC, vGLD at launch) into a market-scoped vault position. success: position/collateral tracked per {owner, market, asset}; multi-asset positions enumerable (Vault: collateral deposit/withdraw task).
- (capability) CAP-2 intent: Borrower borrows a registered third-party stablecoin (USDC at launch) against deposited collateral without any protocol minting. success: borrow reverts if it would breach min ratio, borrow cap, or debt floor; one-time borrow fee applied exactly once at draw; debt recorded as flat principal (Vault: borrow & repay).
- (capability) CAP-3 intent: Borrower repays debt and withdraws collateral, keeping 100% of collateral yield throughout. success: repay reduces principal by exact amount with zero interest growth over time (time-advance test); withdraw succeeds only if remaining position stays >= min ratio when debt > 0.
- (capability) CAP-4 intent: LP supplies/withdraws stablecoin liquidity to a market pool. success: LP receives/burns shares correctly; withdrawal is capped at available on-chain cash (bank-run guard), verified by test (Pool: LP supply/withdraw).
- (capability) CAP-5 intent: LP earns yield solely from the liquidation discount (Mechanism A, pro-rata in-kind via reward-per-token), since the protocol charges no interest. success: cumulative-reward-per-token collateral claims work for LPs; launch borrow-fee-lp-share-bps = 0 (pure liquidation-only, recorded launch decision).
- (capability) CAP-6 intent: Anyone can permissionlessly trigger liquidation of an unhealthy position; no privileged liquidator role exists. success: liquidation reverts when position is healthy; unhealthy position is partially/fully offset using pool funds; liquidation penalty split protocol/LP by protocol-liq-share-bps; optional fixed trigger-reward configurable.
- (capability) CAP-7 intent: Governance onboards any new SIP-010 stablecoin as a borrowable market with zero new contract code and zero redeploys. success: register-market + depeg band + collateral rows via timelock only; full borrow->repay->liquidate lifecycle works post-onboarding in tests; each market isolated (own pool/cap/breaker) (Standard stablecoin onboarding process).
- (capability) CAP-8 intent: Governance configures per-market fees (borrow fee, LP share of borrow fee, protocol liquidation share) within hard, immutable caps, swept permissionlessly to treasury. success: every fee setter rejects values above MAX-BORROW-FEE=200bps/MAX-BORROW-FEE-LP-SHARE=10000bps/MAX-PROTOCOL-LIQ-SHARE=5000bps/MAX-EARLY-REPAY=200bps; sweep-fees callable by anyone, funds land only at governance-set treasury.
- (capability) CAP-9 intent: Protocol automatically pauses new borrows on a market when the borrow-token price deviates beyond a governance-set depeg band from $1, while repay/withdraw stay open. success: price outside band -> new borrows revert, repay/withdraw still succeed; one market's breaker tripping does not affect another market (isolation verified).
- (capability) CAP-10 intent: All admin/governance actions (market CRUD, fee config, treasury, pause, risk params) are routed through a timelock with multisig propose/execute and guardian cancel, except pause which is no-delay emergency fast-path. success: all admin functions callable only via timelock; guardian can cancel a queued action; minimum-delay floor cannot be bypassed.
- (constraint) Fresh, clean-slate mainnet deployment. SSE Finance contracts never call or depend on currently-deployed SSE Core mainnet contracts -- reuse means copying source/patterns, not integrating with a live deployment. Ships its own fresh trait copies (sse-finance-oracle-trait, sse-finance-sip-010-trait).
- (constraint) Interest-free by design: debt is flat principal with no interest-rate model, index, or time-based accrual, at any phase. This is the one decision that shapes everything else (source doc section 0).
- (constraint) No minting or burning of borrow tokens anywhere in SSE Finance. Borrow tokens are plain SIP-010, moved by transfer only; collateral is custodied, never issued.
- (constraint) LP withdrawals are hard-capped at available on-chain cash (the bank-run guard) -- enforced on-chain, no exception path.
- (constraint) Every fee parameter is governance-settable but bounded by hard, code-level MAX-* constants that cannot be raised by governance -- even a compromised multisig cannot exceed them.
- (constraint) Liquidation trigger must stay permissionless; the protocol builds no privileged liquidator role or required bot network. A health-monitor submitter is an optional off-chain convenience only, never protocol-critical.
- (constraint) Each market (per borrowable stablecoin) is fully isolated: own pool-state, borrow cap, depeg band, collateral rows. One market's breaker tripping or cap filling must never affect another market.
- (constraint) New stablecoin onboarding must require zero new contract code and zero redeploys -- governance calls (register-market + config rows) only, proven via a runbook script.
- (non-goal) No interest-rate or accrual-index model, ever (including Phase 2/3) -- any term pricing later is an explicit one-time fee, never accruing interest.
- (non-goal) Phase 1 excludes: tokenized bond/treasury collateral + coupon-claim pass-through, USDA market, institutional/KYC-gated LP pools, Mechanism B (auction) liquidation, fixed-term products -- all explicitly deferred to Phase 2/3.
- (non-goal) No dependency on or integration with the currently-deployed SSE Core mainnet contracts -- SSE Finance is a fresh, self-contained deployment (source-level reuse only).
- (non-goal) No protocol-run liquidator bot network or keeper infrastructure -- liquidation stays permissionless-triggered by design.
- (note) Success signal: end-to-end borrow -> repay and a liquidation demonstrated on mainnet for the first market (USDC + sBTC/vGLD collateral), governance bootstrapped and locked with all admin paths through the timelock, authorized-caller wiring verified before real funds accepted (Deployment & bootstrap task). Secondary signal: onboarding a second stablecoin (e.g. USDA) requires zero new code -- proven by repeating the runbook.
